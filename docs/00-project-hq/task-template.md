# Task: concrete outcome

[All areas](../README.md)

Copy this into the owning area and replace the prompts. For private working notes, put the copy in that area's `private/` folder. Fix relative links after copying; file paths in the fields below should be repository-relative.

| Field | Value |
|---|---|
| Area | Owning folder |
| Mode | Brainstorm / investigate / implement / review |
| Status | Proposed / active / blocked / complete / superseded |
| Updated | YYYY-MM-DD |
| Goal | What the user should be able to do or judge |
| Done when | Concrete acceptance criteria |

## Read first

List only the relevant specification, source files and reference images. Identify the authoritative visual reference when appearance matters.

## Decisions and constraints

Record accepted decisions with their basis. Keep suggestions and unresolved choices separate. List meaningful scope boundaries.

## Current evidence

What exists, what changed, what was actually checked, and what remains uncertain? Separate functional correctness, visual quality and owner approval.

## Open questions and rejected approaches

Record why an approach failed, so the next chat does not repeat it. If iterations stop improving the result, reassess the method against the overall goal before producing more variants.

## Next action

Give the next concrete step and any real dependency. At handoff, note relevant uncommitted files and offline artifacts. On completion, link the canonical document updated and the verification result.
